## The shape of the thing

P0 and P1 are done: the project exists, the contracts are frozen in code, and content is text that a
commandlet imports. The one G1 item never met is "CI builds `Development Editor`": no runner was
ever registered. **P2 (the vertical slice, gate G2) is where the work is now**, and G2 is not close.
The slice needs a player, towers, enemies in a level and a map to put them on. Enemy logic is well
along; tower logic has just started; the player and the map have not.

What that means concretely: every "pure core" in `DFEnemies` and `DFTowers` — the wave plan, the
director, the lane walker, the tower math — is logic with no actor attached. **Nothing spawns yet.**
The first thing that will make this project feel real is an `ADFEnemy` that a director spawns and a
walker moves, and then a Lance that shoots it.

**Every verdict on record so far came from the retired Mac, and the trunk's current state is
unmeasured.** PR #48 was merged through the GitHub UI unbuilt and broke the build
(`DFGameMode.cpp:98` called `GetSubsystemArray<T>()`, which UE 5.8 does not have; `fcc1e1d` fixed it
against the engine headers). PR #51 then merged onto the broken trunk, also unbuilt. The verifying
build after the fix was interrupted, so **whether `unreal/main` compiles now has not been
demonstrated.** No build or test result from the GPU box has been recorded yet;
`unreal/Build/windows-bringup.md` §1 produces the first. Do not assume green.

## The machine (this changed on 2026-09-25)

**The Windows GPU workstation is the only engine machine, and Windows is the only platform**
(ADR-0028, superseding the Mac/GPU-box split of ADR-0023). What follows from that:

- **Setting up and working:** `unreal\deepfield.cmd setup` readies any Windows machine (prerequisites,

  build|test|check|editor|play|host|join` are the everyday commands. [`unreal/README.md`](../README.md),

  [`Build/machines/windows-gpu.md`](../Build/machines/windows-gpu.md), generated by
  `machine-inventory.ps1`: read it rather than assuming, and re-run it after any install.
- **The zsh scripts no longer run anywhere.** `test.sh`, `pr-check.sh`, `int-merge.sh`, `ci-local.sh`,
  `smoke-listen.sh` and `editor-lock.sh` are Mac-pathed. `deepfield test` and `deepfield pr-check`

  WS-15 ports `ci-local`/`int-merge` onto `deepfield.ps1`. The

## Stranded or in flight

- **PR #44, `ws/12-ui/tokens-screens`**: WS-12's UI tokens and the CommonUI screen stack.
  session-fae2d0c5 re-claimed WS-12 on 2026-09-25 to fix it and land it. INT confirmed three findings.
  The one that matters is a design error, not a typo: `DFUIScreenList.inl` puts Hud, Crosshairs,
  Overheads, Prompts, Revive and Endless all on `DF.UI.Layer.Game`, while `UDFUILayout` models a layer
  as one `UCommonActivatableWidgetContainerBase`, and such a container shows exactly one widget at a
  time, deactivating the previous one. Six simultaneously visible pieces of chrome cannot share one
  container: the HUD would be hidden by the crosshair. The other two: `PushScreen` has no duplicate
  guard, and `FindOpenScreen` returns the oldest (buried) instance.

1. **Commission the box, starting with a build of the trunk** (`windows-bringup.md` §1–3):
   `deepfield setup`, then `deepfield test` with no filter (the whole gate), then the smoke, then the

   Today `unreal-checks` is the only lane that runs, so a green PR check means only that the ledger

   ported onto `deepfield.ps1` and a Windows workflow exists. Branch protection requiring the runner's

3. **`ADFEnemy` + `UDFEnemyMovement`** (WS-05, active): the actor that turns three tested cores into
   something that walks down a lane and can be shot.
4. **WS-04 Towers and WS-03 Player** (both active; WS-03 claimed on 2026-09-25): both on the critical
   path, and G2 needs both. A Lance that fires at a walking Drifter is the first time this is a game rather than a library.
5. **WS-28 Match flow** (unclaimed): the director's `OnSpawnRequested` needs a spawner, and
   `ADFMatchState` is what begins the waves.
6. **WS-10a Foundry**: the map the slice happens on. Text-authored terrain plus a redesigned

7. **The render lanes, once the box builds**: perf baselines on `L_Dev_Empty` so the harness exists
   before a map does, then hardware Lumen/Nanite look-dev when WS-10a lands a landform.

## Hazards a new session should know

- **Never test a stale binary.** `deepfield test` builds first and refuses modules older than their
  source; do not pass `-AllowStale` to get past it. If you run the engine's automation by hand, build
  immediately before (runbook §5). The history is in CONTRACTS/ci.md, "A green run on a stale binary".
- **Unbuilt code has been merged twice** (#48, #51), both through the GitHub merge button. Before
  building on either, build it. **Never land with the merge button**: it skips the only step that
  compiles (CONTRACTS/ci.md, 2026-09-25). Land after a build, the gate and the smoke on the box.
- **A green smoke proves less than it did.** Since #48, `PreLogin` runs `ValidateJoinOptions`, and the
  game mode spawns `ADFMatchState`/`ADFPlayerState`/`ADFPlayerController` on every map, including
  `L_Dev_Empty`, which has no lane graph. The smoke's `player joined` ≥ 2 threshold predates that
  validator, so re-derive the pass condition against the new join path before trusting it. WS-05's
  spawn work sits on the far side of that seam.
- **Do not try to run the zsh scripts under Git Bash or WSL.** They hard-code Mac engine paths and
  `.dylib` timestamps. Use the runbook's commands.
- **A single red is unproven: re-run once and say that you re-ran; two reds are a defect**
  (CONTRACTS/ci.md). The rule came from the Mac's memory pressure and stands until INT has GPU-box
  verdicts to judge it by.
- **Leases go stale.** Every lease was stale on 2026-09-24 and was swept (see that digest). A workstream
  marked `paused` has real work in its session log, so read it before starting over.
- **The deterministic headers moved** to `Source/DFCore/Public/Determinism/` (ruling R2). Include
  `Determinism/DFDetMath.h`, not `Waves/DFDetMath.h`.
- **Every open Needs-INT item has been ruled** (`rfcs/needs-int-rulings-2026-09-25.md`, ADRs 0024–0027,
  RFC-0003). Read the ruling before re-raising one.

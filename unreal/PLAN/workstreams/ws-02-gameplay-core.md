- 2026-09-21 · **C4 append (review round 2) — `UDFDamageContext::bAppliesSourceFactors` (default true).** Step.cs applies the shooter's build factor at the WEAPON call site (`weapon.Damage * build.DamageFactor(armored)`, Step.cs:558) and `Damage()` itself applies none, so the two appliers that are not shots carry the row's own number and nothing else: `UpdateStatuses` ticks `def.DamagePerSecond * Balance.Dt` (Step.cs:1041) and a reaction bursts `enemy.MaxHp * reaction.BurstFraction` (Step.cs:1086). `UDFDamageContext::SetStatus` clears the flag and `UDFStatusComponent::ApplyBurst` sets it false; `UDFDamageExecution` then drops every source-side factor — the snapshot-captured `UDFCombatSet.DamageFactor`, the ammo / weak-point / Pack-a-Punch set-by-callers — for those hits. **Behavioural for WS-16 / WS-07:** an Overclocked or Tempest/Glacier-fed hero's burn ticks the row's 0.2, not 1.2 x 0.2 = 0.24, and its thermalShock bursts 12 of 100, not 14.4. The instigator still rides on the context, so bounty / scrap / xp credit is unchanged. A weapon, trap or ability hit leaves the flag true and is untouched.
- 2026-09-21 · **C4 append (review round 2) — `FDFDamageInput::RowFlatArmor` (default -1 = unknown).** Step.cs:545 computes `bool armored = enemyDef.FlatArmor > 0f || enemyDef.FrontArmorArcDegrees > 0f` from the enemy DEFINITION, so shred can never unarmor a target for hollow point's `UnarmoredBonusFactor` (Gunsmith.cs:144-150). `IsArmored()` now reads `RowFlatArmor` when it is set and falls back to the `FlatArmor` attribute when it is not; `UDFDamageExecution` fills it from the FlatArmor capture's aggregator BASE value (`AttemptCalculateCapturedAttributeBaseValue`), which the shred modifier does not move. The flat-armor subtraction still uses the shred-modified attribute. **Behavioural for WS-03 (hollow point):** a shredded Ram at FlatArmor 0 no longer takes the x1.3 unarmored bonus.
- 2026-09-21 · **C5 correction (review round 2) — every slot timestamp is a SERVER timestamp.** `UDFStatusComponent::Now()` now returns `AGameStateBase::GetServerWorldTimeSeconds()` when the world has a game state (and `UWorld::GetTimeSeconds()` when it has none — a dev map or a unit-test world). `FDFStatusSlotRep::EndTimeServer` replicates verbatim and `TimeRemaining()` subtracts the same clock on every machine, so a client that joined 120 s after the server's level load reads a 1.5 s chill as 1.5 s, not 121.5 s. No API or wire-format change; a listen host is bit-identical (delta 0). **WS-13 / WS-14 / any HUD:** `TimeRemaining()` is now safe to read on a client; `EndTimeServer` must never be compared against a client's own `UWorld::GetTimeSeconds()`.

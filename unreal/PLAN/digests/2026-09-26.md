## Interface change: the trunk is `main` (ADR-0029)
`unreal/main` was merged into `main` with a merge commit, so all 208 of its commits, and every
ledger-cited sha that was on it, are on `main`. `unreal/main` is **frozen at `d6a1ce0`**, the WS-15
prep. That commit and the WS-07 prep (`b577aab`) were pushed to `unreal/main` 53 and 13 minutes after
PR #62, while this change was being written, and both were merged in. The freeze is not locked yet
(see "For the human"). `game/` is still deleted at G3; only the branch move was brought forward.

The merge added no C++. `unreal/DeepField/` and `unreal/content/` on `main` are the frozen tip's, and
this change edits only plan documents, runbooks and `unreal/Build` tooling. So the trunk's build state
is exactly what it was: unmeasured since `fcc1e1d` (NEXT.md).

**This change lands as a merge commit** (the PR's *Create a merge commit*) or as a fast-forward push:
never a squash or a rebase, which would cut the 208 commits off `main` (ADR-0029 §1).

What every session does, once:
- **Switch the clone:** `git fetch origin`, `git switch main`, `git merge --ff-only origin/main`.
  Anything still on `unreal/main` builds a frozen tree, and a session that pushes a claim there
  strands it.
- **Retarget branches in flight:** merge or rebase onto `origin/main`, as you did onto
  `origin/unreal/main`. Only your own commits move, because `main` contains all of `unreal/main`.
- **PRs, claims and landings go to `main`:** PROGRAMME.md §6.2, §6.3 and §6.5, and `PLAN/README.md`
  ("Claiming in one command"), now say `main` / `origin/main`.

What moved with it: `unreal-checks` runs on pushes to `main` (its PR trigger was already
branch-agnostic); `unreal-win` builds `main`, which is also the branch it has to live on for its
nightly and its Run workflow button; `deepfield setup` clones `main`, and warns (never switches) when
it finds a clone on `unreal/main`; `ci.yml`'s frozen Godot/sim lanes take the same path filter on
`push` as on `pull_request`, so an Unreal landing does not run them. The Mac-era zsh scripts that no
longer run are retargeted too, so WS-15's `int-merge` port starts from the right trunk.

## Cycle 5 addendum — documentation staleness pass (INT, 06:14Z)

On the owner's ask ("ensure no session will run awry due to outdated .md docs"). All 114 tracked `.md`
files were audited by eight lenses — trunk/branch correctness, platform (ADR-0028), dead paths and
commands, can-a-new-session-start, contracts vs the code, workstream files as live orders,
cross-reference integrity, and two-live-docs-disagree — and every finding was put to two independent
refuters that default to *refuted*. 48 survived, collapsing to 26 distinct defects; all 26 are fixed
here. The refuters killed the rest, almost all for the same reason: **ADR-0028 and ADR-0029 both say
history is left as written**, so a dated session log saying "rebased onto `unreal/main`" or
"DeepFieldEditor Mac Development" is correct as a record and is not a defect. That rule did most of the
work of this audit; it is worth keeping in mind before "fixing" a log line.

**What was actually wrong, grouped by how a session would have been misled.**

1. **A command with no machine.** `WS-07` — the last unclaimed critical-path workstream — told its next
   claimant to "land through `unreal/Build/int-merge.sh`, never the merge button". ADR-0028 left that
   script without a machine, and WS-15 has not ported it, so the brief forbade the only route that
   works and mandated one that does not: a claimant had **no runnable landing path at all**. Replaced
   with the by-hand route (`deepfield ci-local`, regenerate `STATUS.md`, push) and the merge button is
   still refused. The same retired-script pointer was fixed in `rfcs/needs-int-eos-config.md`'s
   unapplied INT checklist (`test.sh` → `deepfield test`, `smoke-listen.sh` → `deepfield smoke`, and
   its §6 "What the Mac editor needs" retitled with the Win64 SDK path marked **unconfirmed** rather
   than guessed), and in `Source/DFUI/README.md`, the one module README in the tree.

2. **A tool that never existed.** `build_level.py` was named as the level/terrain importer in ten live
   places, including PROGRAMME §3.2 — the section whose own heading says *every workstream reads this*
   — and in the Scope lines of WS-09 and WS-30, the first thing a claimant reads. The importers landed
   as `-run=DFLevelImport` and `-run=DFTerrainImport` (RFC-0003 §4 / ruling R7) and only
   `CONTRACTS/lanegraph.md` had been corrected. All ten fixed, plus `registry.json`'s scope strings so
   a rescaffold cannot reintroduce it, and the §3 tree now marks the five other unbuilt `ue-bridge`
   python tools as to-build rather than listing them as if they shipped.

3. **The lock that is not coming.** `NEXT.md`'s Branches table — the canonical place to look up what
   `unreal/main` is — still read "**Not yet locked**: the owner adds a rule … as soon as ADR-0029
   lands; until then INT runs `git log origin/main..origin/unreal/main`". ADR-0029 *has* landed and
   ADR-0030 **declined the lock**, so the table told INT its permanent duty was a droppable stopgap and
   pointed at a ruleset rule the owner has refused. Same conditional in PROGRAMME §6.3. Both now state
   ADR-0030's position: not locked and never will be, the ruleset's `deletion` + `non_fast_forward`
   blocks are the guarantee, and the sweep is permanent.

4. **Contracts that describe code that is not there.** C2 got five corrections against

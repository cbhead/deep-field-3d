# game/assets/towers — integration notes

Generated by `Deep Field 3D - Asset Export.html` (browser build → zip). Source of truth for geometry: `models/*.js`.

## Conventions (DESIGN-BRIEF §2)
- 1 unit = 1 m, Y-up, **-Z forward**. Rest pose bore points -Z; the yaw node rotates about +Y, the pitch node about X with `rotation.x = −pitch` (barrel-up is negative X). Limits and slew rates per tower: `manifest.json` → `rig`.
- Pivot: ground-centre of the 2.1 m socket pad. Barricade: slot centre, wall runs along X, enemies approach from -Z after the forward flip.
- Materials: flat-colour `MeshStandardMaterial`; names `steel_hull`, `chassis`, `energy_<tower>`… — see `palette.json`. Emissive lives only on `energy_*`.

## Files
- `tower_<id>_chassis.glb` — the whole tower at L1 on every path. Contains the rig nodes:
  `<id>_foot` (static) → `<id>_yaw` → `<id>_pitch` → `<id>_muzzle` (empty, `extras.role = projectileSpawn`).
  Aura towers have `<id>_spin` (`extras.role = cosmeticSpin`) instead of a rig.
- `tower_<id>_<path>_s1…s10.glb` — cumulative stage modules: `_sN` holds everything the path has earned through level N. `_s1` is an empty root (the L1 state is in the chassis) so composition is uniform.
  Each module file mirrors the rig skeleton (`<id>_yaw` / `<id>_pitch` empty nodes) so a part that must swing with the barrel sits under the same-named node. **Reparent each module node onto the chassis node of the same name** (or drive the copies with the same rotations).
  Inside, every increment is its own group `<id>_up_<path>_l<N>`, so a module file can also be used additively.
- `tower_barricade.glb` / `_damaged.glb` / `_broken.glb` — 4.5 × 2.2 m wall states for M4 structure HP.

## Runtime cues (optional, procedural)
The viewer animates a few chassis parts per level (e.g. Nova jacket scale, muzzle-brake creep, ready-round visibility). These are listed per tower in `manifest.json` → `cues` as hints; skipping them loses nothing the silhouette needs.

## Replacement site
`GameRoot.SpawnTowerView` — load the chassis, then for each path load `_s<level>` and reparent by node name; swap the stage file on upgrade. Sim ranges/radii remain in `sim/Sim.Core/Content/Towers.cs`.
